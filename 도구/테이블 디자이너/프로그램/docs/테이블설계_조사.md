# 게임 데이터 테이블 설계 — 조사 정리와 반영

조사일: 2026-09-27

자료:
- 강의 「7강 3차시 게임 시스템 설계 심화 — 게임 데이터 설계 및 테이블 작성」
- 실무 글·발표 자료 (아래 출처)

목적: 테이블 디자이너(구조를 처음 만드는 도구)와 그 AI 지시문에 넣을 기준을 정한다.

---

## 1. 강의 핵심 (7강 3차시)

| 주제 | 핵심 |
|---|---|
| 첫 컬럼 | **테이블의 첫 번째 컬럼은 무조건 Index(ID).** 보통 해당 정보의 ID를 쓴다 |
| ID 구간 | **업데이트를 대비해 구간을 나눠 설정** |
| 컬럼 순서 | 우선순위가 높은 컬럼일수록 왼쪽 |
| 컬럼 정보 | 한글 이름·영문 이름·데이터 타입을 쓰고, 타입마다 최소값·최대값을 정한다 |
| 설명서 | 테이블 설명서를 함께 작성한다 |
| 시스템 → 테이블 | 캐릭터 시스템 → 캐릭터 테이블. 몬스터 테이블이 AI·스킬·애니메이션 테이블을 참조 |
| 클라/서버 | 고정 데이터(능력치·스킬)는 클라이언트 테이블, 유동 데이터(레벨·인벤토리·재화)는 서버 테이블 |
| 정규화 | 보통 BCNF까지. 1NF 원자값, 2NF 부분 종속 제거, 3NF 이행 종속 제거 |
| 게임의 예외 | RGB처럼 개수·의미가 고정된 묶음은 배열 허용. 중복 정보는 엑셀 함수로 처리하기도 함 |
| 결과물 | 엑셀 자체가 아니라 CSV·ini 등 게임 포맷으로 바꿔 넣는다 |
| 과제 기준 | 테이블 설명·규격·컬럼명·자료형·한글 설명 필수, 각 테이블 최소 1행 |

## 2. 외부 자료

| 출처 | 적용할 내용 |
|---|---|
| 프로그래머에게 사랑받는 기획서 작성법 | 숫자를 문장에 적지 말고 **파라미터 이름**으로 가리킨다. 프로그래머가 하드코딩할 것과 데이터로 뺄 것을 구분할 수 있어야 한다 |
| NDC 기획서 발표 요약 | 자료형 자체보다 **양수 여부·필요한 범위**가 중요하다. 테이블 이름은 기획자가 읽기 쉽게 짓는다 |
| Game Developer — 스프레드시트 실무 | 행 = 항목, 열 = 속성. 열은 한 화면에 보이게. 값은 목록(드롭다운)으로 통일. 중복 ID는 조건부 서식으로 잡는다 |
| 엔진 데이터 테이블 실무 (Unreal) | 첫 열 = 행 키(고유·공백 없음). 헤더는 코드 필드명과 정확히 같게. 열거형은 정확한 값 이름. 에셋은 경로 문자열로 참조. 한글 CSV는 UTF-8 BOM |
| 게임잡 신입 기획 조언 | 너무 잘게 나누면 안 쓰는 데이터가 늘어난다. 입력 오류는 게임 실행 불가로 이어지므로 검증이 필수 |
| 프라임커리어 테이블 설계 가이드 | 실제로 필요한 정보만 컬럼으로. 확장은 별도 테이블로 나눠 코드 수정 없이 추가 |
| LLM 스키마 정규화 연구 (Miffie, 2025) | 생성 모델과 검증 모델을 나눠 **만들고 → 검사하고 → 고치는** 반복이 정확도를 높인다 |
| 스키마 기반 프롬프트 설계 | 모델에 주는 스키마의 모양(열거 제약, 필드 순서)이 틀린 답의 비율을 좌우한다 |

## 3. 프로그램에 반영한 것 (2026-09-27)

| 항목 | 반영 |
|---|---|
| 첫 열 = PK | 가져오기에 "첫 열을 PK로" 스위치 (기본 켜짐, 기억함). AI가 만든 표는 PK 컬럼을 항상 맨 앞으로 옮김 |
| ID 구간 | AI에 표마다 이미 쓰는 ID 구간(최소~최대)만 알려줘서 새 표가 겹치지 않는 구간을 쓰게 함. 행 내용은 보내지 않음 |
| 한글·영문 이름, 설명, 범위 | AI 작업(create_table, add_column)에 한글 이름·설명·최소·최대 추가. 최소·최대는 검사 규칙이 되어 범위를 벗어난 값을 경고 |
| 설계 원칙 | AI 지시문에 강의·실무 기준 7줄 추가 (시스템 → 테이블, 첫 열 ID, 정규화와 예외, 참조대상_id, 에셋 경로, 예시 행). 서버 테이블은 이 도구 범위 밖(2026-09-28 결정) |
| 구조도 내보내기 | 엑셀 구조도가 앱에 저장된 배치 그대로, 앱처럼 PK·FK만 보이고 나머지는 "+N개 열" |
