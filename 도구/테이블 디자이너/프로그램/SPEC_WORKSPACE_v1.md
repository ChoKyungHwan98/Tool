# 명세서: 워크스페이스 흐름 (대시보드 우선) — v1 DRAFT

> 이 문서는 office-hours 대화의 결과물이다. `PRODUCT_DIRECTION.md`가 "무엇을/왜"라면, 이 문서는 "그래서 화면과 순서를 어떻게"를 정한다.
> 초안이므로 같이 고친다. 결정이 필요한 곳은 §7에 모아뒀다.
> 작성 시작: 2026-07-08

---

## 1. 확정된 방향 (office-hours 결론)

- **목적**: 내가 프로 게임기획자가 됐을 때 실제로 쓸 개인 도구. 단, **판매 제품 기준**으로 만든다. 기준이 더 엄격해서 품질이 올라가기 때문.
- **사용자**: 지금은 나 한 명. "누가 원하나"라는 안개가 걷혔다. 대신 기준이 "내가 내 포폴 테이블을 넣었을 때 Excel보다 나은가"로 바뀐다.
- **wedge (심장)**: 네 통증(참조 깨짐 / 연쇄 수정 / 전체 구조 파악 / 추출+설명서)이 다 real이지만, **"전체 구조를 한눈에"가 근소하게 우위**. GraphLoop에 감명받은 지점이기도 하다. → **그래프 뷰가 이 툴의 히어로다.**
- **재배치 원칙**: 나머지 세 통증은 별도 기능 트랙이 아니라 **그래프 뷰가 눈에 보이게 만들어주는 것들**이다.
  - 참조 깨짐 → 그래프에서 빨간 관계선으로 보인다.
  - 연쇄 영향 → 노드를 클릭하면 연결된 테이블/컬럼이 하이라이트된다.
  - 추출+설명서 → 그래프 구조 그대로 문서가 나온다.
- **순서 결정**: 대시보드(워크스페이스 흐름) 먼저. 단 야망은 자르지 않는다. 순서만 잡는다.

## 2. 핵심 사용자 흐름 (the spine)

이 한 줄이 앱 전체의 척추다. 모든 화면은 이 흐름의 한 칸이다.

```
앱 실행
  → 대시보드 (프로젝트 카드 + 최근 항목 + 새로 만들기 / 열기)
    → 프로젝트 클릭
      → 워크벤치 진입: 그래프 구조도가 먼저 뜬다
        → 테이블 노드 클릭 → 데이터 편집 (Excel형 그리드)
        → 검증 패널: 문제를 그래프와 그리드에 동시에 표시
      → 추출: Excel/CSV export + 자동 설명서 생성
```

**지금과의 차이**: 현재는 앱을 켜면 `initialDocument`(샘플 프로젝트)가 바로 워크벤치로 뜬다. 대시보드도, 프로젝트 목록도, 진짜 열기/저장도 없다. 즉 "제품을 실행한다"가 아니라 "데모가 나타난다"에 가깝다. §3.1이 이 구멍을 메운다.

## 3. 화면별 명세

각 화면은 **목적 / 구성요소 / 상호작용 / 상태(빈·로딩·에러) / 데이터 소스** 순으로 적는다. 판매 제품 기준이므로 빈 상태와 에러 상태를 반드시 명세한다. (기획자가 흔히 빠뜨리는 곳이고, 여기서 조잡함이 드러난다.)

### 3.1 대시보드 (신규 — 최우선)

- **목적**: 앱의 첫 화면. "어떤 프로젝트를 열까"만 결정하는 단순하고 신뢰감 있는 관문.
- **구성요소**
  - 상단: 앱 이름/로고, `새 프로젝트`, `프로젝트 열기(파일)` 버튼.
  - 최근 프로젝트: 카드 그리드. 카드에 프로젝트명, 테이블 수, 마지막 수정일, 썸네일(그래프 미리보기 또는 색 블록).
  - 카드 우클릭/⋯ 메뉴: 이름 변경, 복제, 삭제, 파일 위치 열기.
- **상호작용**
  - 카드 클릭 → 해당 프로젝트를 워크벤치로 로드.
  - `새 프로젝트` → 빈 프로젝트 생성 후 워크벤치 진입 (템플릿 선택은 나중 게이트).
  - `열기` → 파일 다이얼로그(Tauri), `.gsw`(프로젝트 JSON) 또는 CSV 묶음.
- **상태**
  - 빈 상태(최초 실행): "아직 프로젝트가 없어요. 새로 만들거나 CSV를 열어보세요." + 큰 CTA 두 개. 샘플 프로젝트 열기 링크 하나.
  - 로딩: 카드 스켈레톤.
  - 에러(파일 깨짐/못 읽음): 카드에 경고 배지 + "복구 시도 / 원본 열기".
- **데이터 소스**: 최근 프로젝트 목록은 로컬 앱 데이터에 저장(경로 + 메타). 실제 프로젝트 본문은 열 때 로드. → **§4의 store 분리와 직결.** 지금은 `initialDocument`가 모듈 로드시 무조건 생성되는데, 대시보드가 생기면 "프로젝트를 열기 전엔 document가 없음" 상태가 필요하다.

### 3.2 프로젝트 워크벤치 / 그래프 히어로

- **목적**: 프로젝트를 열면 **전체 구조가 먼저** 보인다. 이게 wedge다.
- **구성요소** (현재 `SchemaCanvas` 확장)
  - 캔버스: 테이블 노드(이름, 태그, 컬럼, 타입, PK/FK/REF 배지), FK 관계선.
  - 탐색 도구: `fit view`, zoom, pan, minimap, 테이블 검색, **관계 focus**(한 테이블 선택 시 연결된 것만 강조/나머지 흐리게).
  - 레이아웃: 자동 배치 + 수동 배치. 수동 배치는 저장되고 재오픈 후 유지(`MoveTableLayoutCommand` 이미 있음).
  - 문제 오버레이: 깨진 FK, 고아 참조는 관계선을 빨강/점선으로. 노드 배지에 경고 카운트.
- **상호작용**
  - 노드 클릭 → 인스펙터에 테이블 상세, 연결 하이라이트.
  - 노드 더블클릭 → 데이터 그리드로 전환(그 테이블 선택 상태).
  - 관계선 클릭 → 어느 컬럼→어느 컬럼인지 추적 표시.
- **상태**
  - 빈 프로젝트: "첫 테이블을 만들어보세요" 중앙 CTA.
  - 대형 스키마(수십 테이블): fit view가 기본, 검색으로 점프. **여기서 렉이 제일 심하게 물림 → §4 필수.**
- **데이터 소스**: `document.schema`. **단, 데이터 행과 분리 구독해야 한다(§4).** 지금은 캔버스가 행 편집에도 리렌더된다.

### 3.3 데이터 그리드 (Excel형)

- **목적**: 선택한 테이블의 CSV 데이터를 Excel처럼 편집.
- **구성요소** (현재 `DataGridView` 확장)
  - 고정 헤더 + 행 번호, 셀 선택, 방향키/Enter/Tab 이동.
  - 복사/붙여넣기(다중 셀), 행 추가·삭제·복제, 정렬·필터·검색, 컬럼 폭 조절, 타입 표시.
  - 변경된 셀/행 표시, 셀 단위 검증 오류 표시(이미 있음), 데이터 편집 Undo/Redo.
  - 가상 스크롤(이미 있음 — 창 렌더링 방식).
- **상호작용**: Excel 손맛. 방향키로 이동, 붙여넣기로 블록 입력, Undo로 되돌리기.
- **상태**: 빈 테이블 안내(있음). 대용량(10k행+)에서 입력·스크롤 끊김 없음이 목표.
- **⚠ 현재 렉 핫스팟**: 셀 하나 커밋할 때마다 `validateProjectWithRows(project, 전체 rowsByTable)`가 돈다(280ms 디바운스여도 전체 프로젝트 검증). → §4에서 테이블 단위 증분 검증 + worker로 분리.

### 3.4 검증 패널

- **목적**: 구조·타입·FK·중복·런타임 출력 위험을 한곳에서. 문제를 클릭하면 원인 위치로 점프.
- **구성요소**: 문제 리스트(심각도별), 각 문제 → 테이블/컬럼/행 링크. 그래프와 그리드에 동시 하이라이트.
- **상호작용**: 문제 클릭 → 그리드면 해당 셀로 스크롤, 그래프면 해당 노드/관계선 focus.
- **성능**: 전체 재검증이 아니라 변경분 증분 검증. UI 스레드 안 막기(§4).

### 3.5 추출 + 자동 설명서

- **목적**: 검증된 authoring schema에서 런타임 산출물 재생성 + 사람이 읽을 설명서 자동 생성.
- **구성요소**
  - Export: Excel/CSV, JSON(런타임), FK-path 평탄화(이미 일부 있음).
  - **자동 설명서**: 테이블 목록, 각 테이블의 컬럼·타입·PK/FK·enum·설명, 관계도 이미지(그래프 캡처), 열거형 정의, 버전/생성일. Markdown 또는 HTML로.
- **상호작용**: `추출하기` → 형식 선택 → 폴더 지정 → CSV들 + `README`(설명서) 한 번에.
- **상태**: 검증 실패가 있으면 경고 후 진행 여부 확인. 성공 시 산출물 폴더 열기.
- **데이터 소스**: normalized authoring schema. 런타임 출력은 항상 여기서 재현 가능해야 한다(아키텍처 가드레일).

## 4. 렉 해결 기술 명세 (대시보드 만들면서 같이 한다)

렉을 따로 빼서 고치지 않는다. 대시보드를 만들면 어차피 "프로젝트 로드/언로드"를 위해 store를 손대야 하므로, 그때 같이 뿌리를 고친다. 이게 순서 결정의 핵심 근거다.

### 4.1 원인 (코드로 확인됨)

- `workbenchStore`가 `document` 하나의 거대 객체다. 셀 하나 커밋 → `replaceDocumentRows`로 `revision+1` + `rowsByTable` 통째 교체.
- 모든 컴포넌트가 `document.schema` / `document.rowsByTable`를 **통째로 구독**한다. → 행 하나 바뀌면 `ProjectExplorer`, `DataGridView`, `SchemaCanvas`(ReactFlow), `Inspector`가 **동시에** 리렌더.
- `DataGridView`가 셀 커밋마다 `validateProjectWithRows`로 **프로젝트 전체 검증**을 돈다(validator 1,071줄, 모든 테이블·모든 행).

### 4.2 해법

1. **store 3분리**: `schemaStore`(스키마+레이아웃+Command) / `rowsStore`(테이블별 행) / `uiStore`(선택·뷰·패널). 그래프는 schemaStore만, 그리드는 해당 테이블의 rows만 구독. → 셀 편집이 캔버스를 안 건드린다.
2. **행 데이터 정규화 구독**: `rowsByTable` 통째 교체 대신 테이블 단위로 접근. 그리드는 `rows[selectedTableId]`만 구독.
3. **셀 편집 로컬 커밋 유지**: `CellEditor`가 draft를 로컬로 들고 blur/Enter에만 커밋(이미 그렇게 돼 있음). commit 단위를 더 작게.
4. **증분 검증 + worker**: 전체 재검증 금지. 변경된 테이블만 재검증하고, 무거운 검증은 Web Worker로 UI 스레드에서 뺀다. 검증은 debounce로 배치.
5. **캔버스 스케일링**: 대형 스키마에서 pan/zoom이 부드럽게. 노드 렌더 메모이제이션(변경 없는 노드는 리렌더 스킵), 필요 시 뷰포트 밖 노드 컬링.

### 4.3 측정 기준 (판매 제품 기준)

- 일반 편집 입력 응답: 100ms 이내 체감.
- 스크롤/팬/줌: 눈에 띄는 끊김 없음.
- 10k행 단일 테이블: 기본 편집 가능.
- **검증 방법**: 내가 만든 실제 포폴 테이블 + 10k행 더미로 프로파일링. "타이핑해도 캔버스 안 멈춤"을 눈으로 확인.

## 5. 게이트 순서 (야망 유지, 순서만 재배치)

`PRODUCT_DIRECTION.md`의 8게이트를 이 명세 기준으로 재정렬한다. 범위는 그대로, 순서만.

| 순서 | 게이트 | 핵심 산출물 | 렉 처리 |
|---|---|---|---|
| **A** | 워크스페이스 흐름 | 대시보드, 최근 프로젝트, 새로/열기/저장, 프로젝트 로드·언로드 | **store 3분리 동시 진행 (§4.2 1~3)** |
| **B** | 그래프 히어로 | 대형 스키마 탐색(fit/zoom/minimap/검색/관계 focus), 깨진 참조 시각화, 레이아웃 저장 | 캔버스 스케일링(§4.2 5) |
| **C** | Excel형 그리드 | 붙여넣기·정렬·필터, 데이터 Undo/Redo, 가상화 강화 | 증분 검증+worker(§4.2 4) |
| **D** | 추출 + 자동 설명서 | Excel/CSV export, README 설명서 자동 생성, 관계도 이미지 | — |
| **E** | AI 정규화 | OpenRouter schema-only, Proposal→Command 변환, 승인 후 적용 | (기존 흐름 유지) |
| **F** | 대용량 성능 + 패키징 | 100k행 전략, 설치/보안/릴리즈 QA | 전면 프로파일링 |

- **A가 먼저인 이유**: 대시보드가 없으면 "제품을 실행한다"가 성립 안 한다. 그리고 A에서 store를 어차피 손대므로 렉 뿌리를 같이 뽑는다.
- **B가 두 번째인 이유**: wedge(히어로)라서. 단 A에서 렌더 디커플이 끝나야 캔버스 성능이 산다.
- **각 게이트 완료 정의**: 내 실제 포폴 테이블로 그 게이트 기능을 끝까지 써본다. Excel보다 나으면 통과, 아니면 보류.

## 6. 판매 제품 품질 기준 (게이트마다 통과 체크)

"내 도구지만 팔 수 있는 수준" 기준을 구체화한다. 각 게이트 종료 시 확인.

- [ ] 입력 중 UI가 멈추지 않는다.
- [ ] 모든 화면에 빈 상태·로딩 상태·에러 상태가 있다.
- [ ] 데이터가 유실되지 않는다(저장 실패/앱 종료 시 복구 또는 경고).
- [ ] 처음 켠 사람이 설명 없이 대시보드→프로젝트→편집→추출까지 도달한다.
- [ ] 되돌리기(Undo)가 스키마·데이터 편집 모두에서 동작한다.
- [ ] 파괴적 작업(삭제·머지) 전에 확인·영향 표시가 있다.
- [ ] 한국어 문구가 자연스럽고 일관된다.

## 7. 지금 정해야 할 열린 결정

같이 정할 것들. 여기 답을 채우면 §3~5가 확정된다.
