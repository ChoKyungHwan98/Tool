# 기획서 디자이너

머릿속에 있는 논리와 원고를 먼저 구조화하고, 그 구조에 맞는 디자인 방향과 슬라이드별 레이아웃을 고른 뒤 편집 가능한 PPTX와 Word 문서로 내보내는 한국어 데스크톱 앱입니다.

독립 앱 ID, 데이터 폴더, 버전, 실행 파일, 아이콘과 시작 화면을 사용합니다. Oh My PPT 공개 코드(`v2.2.0`, `78a9a95fcaaba90acca7ea914a4dcb19b9dfb243`)의 편집기·PPTX 입출력·세션 구조를 기반으로 삼았지만, 원본 업데이트 채널과 제품 브랜딩에는 연결되지 않습니다. 그 위에 `DeckIR`, 맥락형 디자인 엔진, 비용 안전 AI 런타임, 기획서 전용 작업 화면을 추가했습니다.

원본 프로젝트의 중국어 안내는 [상류 프로젝트 README](./docs/UPSTREAM_README_ZH.md), 영어 안내는 [README_EN.md](./README_EN.md)에서 확인할 수 있습니다.

## 이 버전이 해결하는 문제

- 회사명·프로젝트명·지원 직무를 고정 입력란으로 받지 않습니다. 자유 원고에서 필요한 맥락 신호를 추출합니다.
- 목차를 단순한 주제 목록이 아니라 장마다 증명할 문장과 논증 순서로 편집합니다.
- 한 가지 템플릿을 반복하지 않습니다. 슬라이드의 논리 구조, 증거 형태, 앞뒤 장의 리듬을 기준으로 레이아웃 후보를 계산합니다.
- 슬라이드마다 네 가지 후보를 보고 직접 선택하거나 해당 장만 다시 계산할 수 있습니다.
- 근거 없는 수치를 만들지 않습니다. 비어 있는 값은 `[DATA REQUIRED]`로 남기고 보고서에 모읍니다.
- API를 호출하지 않고도 원고 편집, 디자인 선택, PPTX·Word 내보내기를 할 수 있습니다.

## 사용 흐름

1. 앱을 열면 바로 새 기획서 작업 화면이 나옵니다.
2. 형식을 신경 쓰지 말고 원고와 메모를 붙여 넣습니다.
3. `근거 추출`로 주장·수치·사례·이미지 요구를 인벤토리로 만듭니다.
4. `논리 목차 제안`을 실행하고 슬라이드별 주장과 본문을 직접 다듬습니다.
5. 원고에서 도출된 디자인 방향 2–3안 중 하나를 고릅니다.
6. 슬라이드별 네 가지 레이아웃 후보를 확인하고 필요한 장만 교체하거나 다시 계산합니다.
7. `PPTX` 또는 `Word`로 내보냅니다. 내보내기 자체는 AI나 외부 API를 호출하지 않습니다.

## AI 비용 모드

기본 우선순위는 다음과 같습니다.

1. `Codex 구독`: 현재 로그인된 Codex/ChatGPT 구독 범위에서 구조화 작업을 수행합니다. 별도의 OpenAI API 키를 요구하지 않습니다.
2. `오프라인`: AI 호출 없이 직접 편집하고 레이아웃 엔진과 Office 내보내기만 사용합니다.
3. `OpenRouter`: 사용자가 명시적으로 켠 경우에만 사용합니다. 월 예산과 요청별 예상 비용 검사를 통과해야 호출합니다.

OpenRouter 키는 설정 화면에서만 관리하며 화면·로그·렌더러 IPC로 평문을 돌려주지 않습니다. API 공급자를 바꿔도 DeckIR, 디자인 엔진, PPTX·Word 출력 구조는 바뀌지 않습니다.

## 출력물

### PPTX

- 13.333 × 7.5인치, 16:9
- 편집 가능한 라이브 텍스트와 네이티브 도형
- 선택한 디자인 방향과 슬라이드별 레이아웃 반영
- 이미지 슬롯 설명·해상도·주석을 별도 도형으로 유지
- 슬라이드 노트에 `[Sources]` 근거 매핑 기록
- 파일 옆에 `.report.json` 감사 보고서 생성

### Word

- 실제 Word 스타일과 글머리표 번호 체계
- 머리글, 페이지 번호, 고정 폭 콘텐츠 매핑 표
- `[DATA REQUIRED]`, 이미지 요구, AI 문체 점검 부록
- 파일 옆에 `.report.json` 감사 보고서 생성

Pretendard가 설치되지 않은 컴퓨터에서는 PowerPoint나 Word가 호환 글꼴로 대체할 수 있습니다. 이 경우에도 텍스트는 편집 가능한 상태로 남습니다.

## 개발 실행

Node.js 20 이상과 pnpm 10이 필요합니다.

```powershell
corepack pnpm@10.10.0 install
corepack pnpm@10.10.0 dev
```

프로젝트 규칙에 따라 `npm run lint`와 `npm run build`는 검증 명령으로 사용하지 않습니다. 기능 검증은 관련 Vitest와 두 타입 검사로 수행합니다.

```powershell
corepack pnpm@10.10.0 exec vitest run
corepack pnpm@10.10.0 run typecheck:node
corepack pnpm@10.10.0 run typecheck:web
```

## 구조

| 영역             | 위치                                               | 역할                                                    |
| ---------------- | -------------------------------------------------- | ------------------------------------------------------- |
| 기획서 작업 화면 | `src/renderer/src/pages/deck-designer.tsx`         | 자유 입력, 목차 수정, 디자인·레이아웃 선택, 내보내기    |
| 기획서 보관함    | `src/renderer/src/pages/deck-designer-library.tsx` | 작업공간 검색·재진입                                    |
| DeckIR           | `src/shared/deck-ir/`                              | 원고·근거·주장·슬라이드·데이터 요구·이미지 슬롯의 정본  |
| 디자인 엔진      | `src/shared/design-engine/`                        | 맥락 신호, 디자인 방향, 레이아웃 후보, 덱 리듬 계산     |
| 구조화 AI        | `src/main/agent-runtime/structured/`               | Codex·OpenRouter·오프라인 공급자                        |
| 비용 안전장치    | `src/shared/ai-budget.ts`                          | 예산 정규화와 호출 허용 판단                            |
| PPTX·Word 출력   | `src/main/io/deck-ir-export/`                      | 편집 가능한 Office 파일과 감사 보고서 생성              |
| 저장·IPC         | `src/main/deck-ir/`                                | revision, checksum, 단계 실행, 부분 수정, 내보내기 연결 |

상세 설계와 6단계 구현 범위는 [기획서 디자이너 설계 문서](./DECK_DESIGNER_KO.md)를 참고하세요.
