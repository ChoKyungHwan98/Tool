# 기획서 디자이너 1~5단계 이식 구조

## 목적

기존 Electron 프로그램의 창, 업데이트, 사이드바, IPC를 다시 띄우지 않고 게임기획 스튜디오의 동일 탭 안에서 기획서 작성 흐름을 제공합니다.

## 재사용한 핵심

- `DeckIR`: 원문, 근거 인벤토리, 슬라이드, 디자인 계획의 추적 가능한 문서 모델
- 디자인 엔진: 논리 구조와 정보 밀도에 따른 장별 레이아웃 후보 계산
- PPTX·Word 빌더: 편집 가능한 Office 문서와 무결성 보고서 생성

## 스튜디오 전용 경계

- 진입점: `도구/기획서 디자이너/프로젝트/studio`
- 배포 경로: `app/assets/ui/tools/deck`
- 스튜디오 연결: `/tools/deck/index.html?host=studio&workspaceId=...`
- 저장: 작업공간의 네이티브 아티팩트 저장소. revision 충돌 검사, 원자적 교체, 최근 20개 백업을 사용
- 기본 동작: API 없는 로컬 초안

기존 Electron 업데이트 검사, 별도 창, 중국어 원본 UI와 Electron 전용 IPC는 스튜디오 빌드에 포함하지 않습니다.

## 완성된 1~5단계

### 1. 작업공간 영속성

- 기획서 라이브러리를 `artifact:load/save` 브리지로 저장합니다.
- 저장 revision이 어긋나면 조용히 덮어쓰지 않고 충돌 화면에서 다시 읽기 또는 강제 저장을 선택합니다.
- 브라우저 저장본이 있으면 최초 한 번 네이티브 저장소로 옮깁니다.

### 2. 시각 슬라이드 편집

- 실제 16:9 비율로 선택 장을 미리 봅니다.
- 제목 크기와 정보 밀도를 장별로 조절합니다.
- 이미지 설명, 구도, 비율, 최소 해상도와 주석을 편집하고 PPTX의 라이브 도형으로 유지합니다.

### 3. Office 출력 사전검사

- 다운로드 전에 PPTX·DOCX를 메모리에서 실제로 생성합니다.
- ZIP 패키지, 필수 Office 파트, XML 문법, 16:9, 슬라이드 수, 라이브 텍스트와 화면 경계를 검사합니다.
- 오류가 있으면 다운로드를 막고 장·요소 단위로 보고합니다.

### 4. 선택형 OpenRouter

- API 없이 작성·편집·출력이 모두 동작합니다.
- OpenRouter 키는 Windows 자격 증명 관리자에 저장하며 렌더러로 되돌려 주지 않습니다.
- 모델별 입력·출력·고정 요청 가격으로 호출 전 비용을 추정하고 네이티브 계층에서 월/요청 한도를 재검사합니다.
- AI 결과는 제안으로만 표시하며, 인벤토리에 없는 근거 ID와 새 수치는 적용 단계에서 거부합니다.

### 5. 도구 자료 연결

- 테이블·패턴 디자이너가 작업공간 카탈로그에 읽기 전용 스냅샷을 발행합니다.
- 기획서에서 사용자가 명시적으로 참조·최신화·해제합니다. 도구를 열기만 해서는 연결되지 않습니다.
- 테이블 셀과 패턴 노드·연결선은 스크린샷이 아니라 편집 가능한 PowerPoint 텍스트·도형으로 삽입됩니다.

## 현재 사용자 흐름

1. 자유 원고와 제목을 입력합니다.
2. 원문을 근거 인벤토리와 슬라이드별 주장으로 나눕니다.
3. 원고의 증거 형태와 논리 구조에서 세 디자인 방향을 제안합니다.
4. 선택한 방향으로 각 장의 레이아웃 후보를 계산합니다.
5. 필요하면 슬라이드 미리보기에서 글자 크기, 밀도와 이미지 슬롯을 다듬습니다.
6. 필요할 때만 OpenRouter 제안을 요청하고 검토 후 적용합니다.
7. 작업공간의 테이블·패턴 자료를 명시적으로 참조해 벡터 슬라이드로 삽입합니다.
8. 실제 Office 패키지 사전검사를 통과한 PPTX·Word와 검증 보고서를 내려받습니다.

## 제품화 경계

1~5단계는 기능 기반을 완성한 범위입니다. 상용 배포 판정과 남은 조건은 `PRODUCT_READINESS_KO.md`를 정본으로 사용합니다.
