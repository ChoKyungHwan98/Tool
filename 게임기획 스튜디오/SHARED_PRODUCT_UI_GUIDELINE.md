상태: 2026-09-15 사용자 승인, 2026-09-22 프로젝트 홈 상호작용 계약 추가(폴더에서 빼기·삭제 경로 포함), 목록형 홈 허용 명시. 이후 이 제품군의 **도구 홈 화면**을 만들거나 수정할 때 이 지침을 기본값으로 사용한다. 기준 구현은 `도구/AI 리뷰데이터 분석/프로그램/static/index.html`이고, 같은 구조를 적용한 결과는 `도구/PPT 디자이너/game-ppt-designer-next/apps/workbench/src/StudioWorkbench.tsx`와 `styles.css`에 있다. 아래 「프로젝트 홈 상호작용 계약」의 기준 구현은 `도구/PPT 디자이너/game-ppt-designer-next/apps/workbench/src/ProjectHomeLauncher.tsx`와 `게임기획 스튜디오/ui/src/ProjectLauncher.tsx` 두 곳이며, 두 파일은 같은 규칙을 따른다. 두 화면에서 실제로 확인한 값만 기준으로 기록한다. 이 지침은 장표 내용·Renderer·출력물 스타일에 적용되는 규칙이 아니다.

## 화면 흐름

홈(`전체 프로젝트`·도구별 관리 기능) → 프로젝트 → 필요한 경우 작업 방식 선택 → 작업 화면. 프로젝트와 작업 화면에서는 `← 전체 프로젝트`로 홈에 돌아갈 수 있어야 한다. `최근 작업`을 별도의 홈 사이드바 메뉴로 추가하지 않고 프로젝트 내부에서 보여준다. AI 학습과 모델 관리는 프로젝트 내부에 넣지 않고 홈에서 접근한다. 프로젝트는 그 도구 내부의 작업 단위다.

## 글자 기준 — 모든 화면 (스튜디오 + 모든 도구)

홈만이 아니라 **작업 화면·대화상자·패널까지** 이 기준을 쓴다. 빌드할 때 `scripts/check-tool-guidelines.mjs`가 자동으로 검사하고, 어기면 빌드가 멈춘다.

**글꼴**: 아래 스택 하나만 쓴다. 코드·ID·단축키처럼 글자 폭이 같아야 하는 곳만 고정폭(`Consolas`, `JetBrains Mono` 등)을 쓴다. `Inter`, `Segoe UI`를 맨 앞에 두는 도구별 스택을 만들지 않는다.

```css
font-family: 'Pretendard Variable', Pretendard, -apple-system, BlinkMacSystemFont, system-ui, Roboto,
  'Helvetica Neue', 'Segoe UI', 'Apple SD Gothic Neo', 'Noto Sans KR', 'Malgun Gothic', sans-serif;
```

**크기 단계**: 아래 값만 쓴다. 중간값(11.5px, 17px 등)을 새로 만들지 않는다.

| 크기 | 쓰임 |
| --- | --- |
| `12px` | **최소값.** 배지, 시각, 단축키 설명, 표 머리글 보조 |
| `13px` | 보조 정보, 그룹 라벨, 표 머리글 |
| `14px` | **기본 본문**, 목록 항목, 입력칸, 표 셀 |
| `15px` | 메뉴, 검색 입력, 주요 버튼 |
| `16px` | 패널·카드 섹션 제목 |
| `18px` | 카드 제목, 대화상자 제목 |
| `20px` | 사이드바 제품명, 작업 화면 제목 |
| `24px` | 홈 제목 |
| `28px` · `32px` · `40px` · `48px` | 큰 숫자(지표) 전용 |

**굵기**: `400` 본문 · `500` 메뉴·버튼 · `600` 라벨·강조 · `700` 제목. 그 밖의 값(650, 800 등)은 쓰지 않는다. 선택 상태에서 굵기를 바꿔 글자가 흔들리게 하지 않는다.

**줄높이**: 본문 `1.5`, 여러 줄 설명 `1.6`, 제목 `1.3`, 입력·버튼 `normal`.

**숫자**: 표·지표의 숫자는 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다.

**예외**: 카드 미리보기·축소판처럼 **그림으로 보이는 축소 화면 속 글자**는 크기 단계에서 뺀다. 검사 스크립트가 선택자 이름에 `thumb`, `sample-pages`, `slide-label`, `mini-map`, `map-node`, `preview-window`, `table-cell`, `pattern-node`, `connection-wire`, `kbd`가 들어간 규칙은 건너뛴다. 장표 본문·출력물 글자는 이 기준 밖이다.

### 홈 화면 세부 값

폰트 우선순위: `Pretendard Variable`, `Pretendard`, `-apple-system`, `BlinkMacSystemFont`, `system-ui`, `Roboto`, `Helvetica Neue`, `Segoe UI`, `Apple SD Gothic Neo`, `Noto Sans KR`, `Malgun Gothic`, `sans-serif`. 검색 입력·버튼에도 같은 스택을 적용한다. 글자 렌더링은 `text-rendering: auto`, `font-synthesis: weight style small-caps`로 통일한다. 기본은 `14px / 1.5`, 홈 제목은 `24px / 700 / 1.5`(실제 줄높이 36px), 사이드바 제품명은 `20px / 700`, 메뉴는 `15px / 500`, 그룹 라벨은 `13px / 600`, 프로젝트 카드 제목은 `18px / 700`, 보조 정보는 `13px`. 검색 입력과 주요 버튼은 `15px`, 입력과 버튼의 `line-height`는 `normal`로 맞춘다. 화면을 채우기 위해 8~11px의 아주 작은 UI 글자를 기본값으로 쓰지 않는다. 기본 제목의 과한 자간 축소와 의미 없는 영어 라벨을 피한다.

## 레이아웃과 표면

- 홈 사이드바: 너비 `260px`, 내부 여백 `24px 16px`, 흰 배경, 오른쪽 `1px` 경계선. 제품명 아래 `40px` 간격, 탐색 그룹 간 `24px` 간격.
- 스튜디오 안의 홈 패널: 바깥 모서리 `16px`, `overflow: hidden`. 모서리 밖의 노출 바탕은 `#F2F2F4`; 따뜻한 회색이나 어두운 iframe 배경이 테두리처럼 드러나면 안 된다. 바깥쪽 아이콘 레일은 **공통 스튜디오 UI**이며 도구의 사이드바나 제품명 로고가 아니다. 제품명 앞의 로고와 프로젝트 탐색 문구 앞의 아이콘은 표시하지 않는다. 홈 사이드바의 프로젝트 탐색은 기준 화면처럼 `전체 프로젝트` 하나만 두고, 최근 생성물은 프로젝트 내부에서 보여준다.
- 선택 메뉴: `12px` 둥근 모서리, `12px 16px` 여백, `15px / 500`, 제목색. 선택 상태는 연회색 배경, 파란 글자(`#1B64DA`), 왼쪽 `4px` 위치의 `3px × 16px` 파란 막대(항목 높이 전체가 아니다). 선택됐다고 글자 두께를 바꿔 위치가 흔들리지 않게 한다.
- 홈 본문: `40px 60px` 여백. 제목/검색·새 프로젝트 버튼과 카드 그리드를 분리하고, 헤더 아래 `32px` 간격. 스크롤바 너비는 `10px`로 고정해 본문·검색·카드의 가로 위치가 도구마다 달라지지 않게 한다.
- 헤더 조작: 검색 입력과 주요 버튼을 오른쪽에 두고 둘 사이 `16px` 간격. 검색은 별도 아이콘 요소를 감싼 label이 아니라 **입력칸 하나**로 만든다. 크기 `280px × 44px`, `12px` 둥근 모서리, `15px / 400 / normal`, 왼쪽 `16px`·오른쪽 `40px`·상하 `12px` 여백, `rgba(255,255,255,.6)` 바탕, 투명 `1px` 테두리. `16px` 검색 아이콘은 오른쪽 `12px`에 background image로 표시한다. focus 시 흰 바탕과 `#3182F6` 테두리를 사용한다. 별도 flex SVG를 넣어 글자 시작점과 아이콘 크기를 흔들지 않는다. 주요 버튼은 최소 `143px × 42px`, `15px / 600 / normal`, `12px` 둥근 모서리, 좌우 `20px` 여백, 왼쪽 정렬, `16px` `+` 아이콘과 문구 사이 `6px`. 기능별 문구가 달라도 검색창의 시작 위치가 흔들리지 않도록 오른쪽 정렬과 버튼 최소 폭을 유지한다.
- 프로젝트 그리드: `minmax(280px, 1fr)` 자동 채움, `24px` 간격. 카드: `16px` 여백, `24px` 둥근 모서리, 흰 배경, `0 4px 20px rgba(0,0,0,.06)` 그림자. 미리보기: 높이 `160px`, `16px` 둥근 모서리, 아래 `20px` 간격.
- **목록형 홈도 쓸 수 있다.** 프로젝트마다 볼거리가 아니라 수치(테이블 수, 행 수, 수정 시각)가 중요한 도구는 카드 그리드 대신 표를 쓴다. 기준 구현은 `도구/테이블 디자이너/프로그램`이다. 이때도 공통 색·글자·사이드바·검색·주요 버튼 규격은 그대로 지키고, 목록 카드만 `16px` 둥근 모서리에 흰 배경, `1px #E5E8EB` 경계선, `0 4px 20px rgba(0,0,0,.06)` 그림자를 쓴다. 머리글 행은 `44px`에 `13px / 600` 보조 글자색, 각 행은 `56px`에 이름 `15px / 600`, 수치 `14px`, 시각 `13px` 보조 글자색으로 둔다.
- 탐색 항목 문구 앞에 아이콘을 붙이지 않는다. 탐색 항목이 여럿인 도구도 같다(레일이 접히는 좁은 창에서만 아이콘을 보인다). 선택 상태는 연회색 배경 + 파란 글자 + 왼쪽 `3px × 16px` 파란 막대, 글자 두께 불변. 문구 뒤에 개수를 붙이지 않는다.
- 일반 작은 모서리 `8px`, 버튼/메뉴 `12px`, 미리보기/작업 패널 `16px`, 프로젝트 카드 `24px`. 경계선보다 여백·글자 위계로 그룹을 먼저 구분한다.
- 홈 하단 도구 메뉴: 위쪽 `1px` 경계선과 `16px` 여백, 메뉴 각각 높이 `42px`, `14px` 보조 글자색. AI 학습·모델 관리처럼 기능명 자체가 분명하면 불필요한 별도 그룹 라벨을 붙이지 않는다.

## 프로젝트 홈 상호작용 계약

`전체 프로젝트` 화면은 보기만이 아니라 정해진 조작 규칙을 가진다. 새 도구에 이 화면을 붙일 때 아래 동작을 그대로 구현한다. 수치는 기준 구현에서 실제로 쓰는 값이다.

**우클릭 삭제는 모든 도구가 갖춘다. 폴더는 선택이다.** 프로젝트가 몇 개 되지 않거나 묶을 축이 없는 도구는 폴더를 넣지 않는다. 예를 들어 `도구/AI 리뷰데이터 분석/프로그램/static/index.html`은 목록과 삭제만 쓰고 폴더를 두지 않는다. 폴더를 넣기로 했다면 아래 규칙을 전부 지킨다. 절반만 구현하면 폴더를 만들 수는 있는데 풀 수 없는 상태가 된다.

### 배열과 폴더

| 규칙 | 값 |
| --- | --- |
| 끌기 시작 | 길게 누르기 `480ms`. 편집 모드에서는 즉시 |
| 끌기 취소 | 길게 누르기 전에 `8px` 넘게 움직이면 취소 |
| 합치기 판정 영역 | 대상 카드의 가로 `27%~73%`, 세로 `20%~80%` |
| 순서 이동 판정 | 합치기 영역 밖. 가로 `50%` 이상이면 대상 뒤, 미만이면 앞 |
| 폴더 자동 해제 | 폴더에 프로젝트가 1개만 남으면 폴더를 없애고 그 프로젝트를 그리드로 되돌린다 |
| 배열 저장 | `localStorage`. 키는 `<도구 이름>:project-home-layout:v1` 형태로 도구마다 따로 쓴다 |

**폴더는 어떤 것과도 합쳐지지 않는다.** 폴더를 끌면 대상이 폴더든 프로젝트든 언제나 순서만 바뀐다. 데이터에서 막는 것으로 끝내지 말고, 끌고 있는 항목이 폴더면 합치기 강조(`is-folder-target`)를 아예 띄우지 않는다. 합쳐질 것처럼 보였다가 순서만 바뀌면 사용자는 기능이 고장 났다고 읽는다. 판정은 `canCombineHomeEntries`처럼 **한 함수**로 모아 끌기 강조와 실제 드롭이 같은 근거를 쓰게 한다.

### 우클릭 메뉴

프로젝트 카드와 폴더 카드 **모두** 우클릭 메뉴를 가진다. 폴더에 메뉴가 없으면 사용자는 폴더를 지울 방법을 찾지 못한다.

| 대상 | 메뉴 |
| --- | --- |
| 프로젝트 카드 | `프로젝트 삭제` — 확인 대화상자를 거쳐 도구 휴지통으로 옮긴다 |
| 폴더 카드 | `폴더 열기`, `폴더 삭제` |
| 폴더 안 카드 | 프로젝트 카드와 같은 메뉴 |

`폴더 삭제`는 **폴더만 없애고 안에 있던 프로젝트는 홈 그리드로 되돌린다.** 프로젝트를 함께 지우지 않는다. 파괴적이지 않은 항목(`폴더 열기`)은 빨간색을 쓰지 않는다.

**폴더에서 빼기는 편집 모드 뒤에 숨기지 않는다.** 폴더를 연 사람은 편집 모드를 켜는 방법을 모르는 상태다. 폴더 안 카드 아래에 항상 보이는 버튼과 우클릭 메뉴 양쪽에서 뺄 수 있어야 한다. 뺀 프로젝트는 홈 그리드 끝에 붙이고, 폴더에 하나만 남으면 폴더도 함께 푼다.

메뉴는 `contextmenu` 이벤트와 **오른쪽 버튼 `pointerdown` 양쪽**에서 연다. 스튜디오 호스트가 `put_AreDefaultContextMenusEnabled(FALSE)`로 WebView2 기본 메뉴를 끄기 때문에, 한쪽 경로만 쓰면 도구에 따라 메뉴가 열리지 않을 수 있다. 오른쪽 버튼 `pointerdown`에서는 `stopPropagation`을 함께 호출한다. 그러지 않으면 "빈 곳을 누르면 메뉴를 닫는다"는 전역 처리기가 방금 연 메뉴를 곧바로 닫는다.

### 서버에 지우는 삭제

삭제가 로컬 배열이 아니라 서버를 거치면 두 가지를 반드시 확인한다. 둘 중 하나만 빠져도 사용자에게는 "메뉴는 뜨는데 눌러도 아무 일이 없다"로 보인다.

- **서버의 CORS 허용 메서드에 `DELETE`를 넣는다.** 도구 화면은 도구 서버와 다른 출처에서 뜨므로 `DELETE`는 프리플라이트를 거친다. `Access-Control-Allow-Methods`에 `GET, POST`만 있으면 요청 자체가 나가지 못한다.
- **`fetch`를 `try`로 감싼다.** 서버가 꺼져 있으면 예외가 나고, 이를 잡지 않으면 삭제가 아무 표시 없이 사라진다. 실패했을 때는 화면에 이유를 남긴다.

삭제는 지우지 말고 도구별 휴지통으로 **옮긴다.** 기준 구현은 `<프로젝트 저장소>/.ppt-designer-trash`와 `<프로젝트 저장소>/.review-trash`를 쓴다.

### 도구가 자기 서버로 화면을 줄 때

도구 화면을 자체 HTTP 서버가 내려주면 **HTML 응답에 `Cache-Control: no-cache`를 붙인다.** 주소가 `/`처럼 고정이고 캐시 헤더가 없으면 브라우저는 `Last-Modified`만 보고 스스로 유효 기간을 정한다. 파일이 오래 안 바뀌었을수록 더 길게 잡기 때문에, 화면을 고쳐도 스튜디오의 WebView2가 옛 화면을 계속 띄운다. 이때 코드는 멀쩡한데 기능이 없는 것처럼 보이므로 원인을 찾기 어렵다. `ETag`는 그대로 두면 바뀌지 않았을 때 304로 끝난다. 스튜디오 자산처럼 파일 이름에 해시가 붙는 경우는 해당하지 않는다.

### 폴더 안 화면

폴더를 열면 나오는 카드는 **홈 그리드 카드와 같은 미리보기를 쓴다.** 이름만 있는 흰 상자를 쓰지 않는다. 결과물 이미지가 있으면 그 이미지를, 없으면 홈 카드와 같은 기본 미리보기(문서 종류 + 제목)를 보여준다. 폴더 카드의 4칸 미리보기도 마찬가지로 실제 결과물 이미지를 채운다.

폴더 안 카드는 홈 카드보다 작게 쓴다. 기준 구현은 미리보기 높이 `124px`, 카드 모서리 `18px`, 그리드 `minmax(232px, 1fr)`를 쓴다. 홈 그리드는 미리보기 `160px`, 모서리 `24px`, `minmax(280px, 1fr)`이다.

### 마우스 사이드 버튼

마우스 4번 버튼은 뒤로, 5번 버튼은 앞으로 이동한다. `mouseup`에서 처리하고, `mousedown`과 `auxclick`에서는 `preventDefault`로 호스트의 기본 앞뒤 이동을 막는다.

뒤로 가기는 **열려 있는 겹침 화면을 먼저 닫는다.** 순서는 `우클릭 메뉴 → 삭제 확인 → 폴더 안 화면 → 편집 모드 → 화면 이동`이다. 닫을 것이 없을 때만 이전 화면으로 넘어간다. 겹침 화면을 건너뛰고 화면을 바꾸면 사용자는 방금 연 폴더를 잃는다.

화면 이동 기록은 방문한 화면을 쌓는 스택 두 개(뒤로·앞으로)로 관리한다. 새 화면으로 이동하면 앞으로 스택을 비운다. 사이드 버튼으로 이동한 경우에는 기록을 다시 쌓지 않는다.

### ⚠ 스튜디오와 도구 사이의 뒤로가기 계약 (모든 도구 필수)

스튜디오 **상단 왼쪽의 `←` 버튼이 이미 뒤로가기다.** 도구 작업 화면에 "프로젝트 목록으로" 같은 별도의 홈·뒤로 버튼을 또 두지 않는다. 도구가 스튜디오 밖에서 단독 실행될 때만 보인다(`host=studio`가 아닐 때).

도구는 스튜디오 안에서 iframe으로 뜬다. iframe 위에서 누른 사이드 버튼은 스튜디오에 전달되지 않으므로 **모든 도구가 아래 두 가지를 직접 구현한다.** 메시지 채널은 `game-design-studio:tool-navigation`이다.

| 상황 | 도구가 할 일 |
| --- | --- |
| 사이드 버튼(4·5번) | 도구 안 화면 기록으로 이동한다. **갈 곳이 없으면** 부모에 `{ type: 'side-navigate', direction: 'back' \| 'forward' }`를 보낸다. 스튜디오가 자기 화면 기록으로 이동한다 |
| 스튜디오 `←` 버튼 | 스튜디오가 `{ type: 'navigate-back', requestId }`를 보낸다. 도구는 안에서 뒤로 갔으면 `handled: true`, 갈 곳이 없으면 `false`로 `{ type: 'navigate-back:result', requestId, handled }`를 350ms 안에 답한다 |

- 도구 안 "화면"은 사용자가 위치로 느끼는 것이다: 홈 목록 → 프로젝트 → 보기 전환(예: 전체 구조·테이블 편집·테이블 설계).
- 자체 서버에서 뜨는 도구(AI 리뷰데이터 분석, `127.0.0.1:8765`)는 스튜디오가 그 주소로 메시지를 보낸다. 새 자체 서버 도구를 추가하면 `ui/src/App.tsx`의 주소 목록에 넣는다.
- 기준 구현: `도구/테이블 디자이너/프로그램/src/presentation/state/screenHistory.ts`(여러 단계 화면), `도구/패턴 디자이너/src/editor/screenHistory.ts`(두 화면), `도구/AI 리뷰데이터 분석/프로그램/static/studio-nav.js`(페이지 이동형).
- 검증: 스튜디오 안에서 도구 홈 → 프로젝트 → 다른 보기로 간 뒤 4번을 눌러 한 칸씩 돌아오고, 도구 홈에서 한 번 더 누르면 도구 보관함으로 나가야 한다. 5번으로 다시 들어와야 한다. 상단 `←`도 같은 순서로 동작해야 한다.

### 이 화면에서 검증할 것

- 프로젝트 카드와 폴더 카드 각각에서 우클릭 메뉴가 열린다.
- 폴더를 다른 폴더에, 그리고 프로젝트에 겹쳐도 합쳐지지 않고 순서만 바뀐다. 겹치는 동안 합치기 강조가 뜨지 않는다.
- `폴더 삭제` 뒤 폴더 안에 있던 프로젝트가 모두 홈 그리드에 남아 있다.
- (폴더를 쓰는 도구만) 편집 모드를 켜지 않은 상태에서 폴더 안 항목을 밖으로 뺄 수 있다. 버튼과 우클릭 메뉴 양쪽으로 확인한다.
- 프로젝트 삭제가 실제로 목록과 저장소에서 빠지고 휴지통에 남는다. 서버를 끈 상태에서도 눌러 보고, 화면에 실패 이유가 뜨는지 확인한다.
- 화면을 고친 뒤 스튜디오에서 실제로 바뀐 화면이 뜨는지 본다. 브라우저에서는 되는데 스튜디오에서만 옛 화면이면 캐시 헤더를 먼저 의심한다.
- 폴더를 열었을 때 카드에 미리보기가 보인다.
- 사이드 버튼 뒤로가 폴더 안 화면을 먼저 닫고, 그다음 눌렀을 때 이전 화면으로 간다. 앞으로가 되돌아온다.
- 배열·폴더 규칙은 순수 함수로 분리해 단위 테스트로 고정한다. 기준 구현은 `ProjectHomeLauncher.test.ts`와 `ProjectLauncher.test.ts`에 있다.

## 지우거나 만들지 않을 것

제품명 앞의 장식용 큐브/한 글자 로고, `전체 프로젝트` 뒤의 프로젝트 개수 표시, 데이터와 무관한 영어 장식 문구는 사용하지 않는다. 중요한 기능을 작은 글자로 숨기지 않는다. 다른 도구의 실제 이미지나 IP는 복제하지 않는다. 각 도구의 작업 화면은 기능에 맞게 달라도 되지만 공통 색·글자·표면 기준을 벗어나지 않는다.

## 검증

홈 → 프로젝트 → 작업 방식(필요한 도구) → 작업 화면 → 홈 이동이 가능해야 한다. AI 관리 진입은 홈에서만 가능해야 한다. 좁은 창에서도 주요 조작이 사라지지 않아야 하며, 글자 잘림·겹침이 없어야 한다. UI 변경 시 두 도구를 **같은 스튜디오 프레임·같은 뷰포트**에서 눈으로 비교하고 해당 도구의 기존 테스트를 통과시킨다. 좌표만 비교하지 말고 검색 입력/버튼의 computed `font-family`, `font-size`, `font-weight`, `line-height`, `padding`, `background`, `border-radius`, 아이콘 크기·위치와 모서리 뒤의 색상까지 확인한다. 도구별 데이터나 기능 문구 차이를 공통 레이아웃 실패로 오해하지 않는다.
